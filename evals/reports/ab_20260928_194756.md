## Verdict

- shipped hybrid vs vector_only: recall@5 0.983 -> 0.950 (**-0.033**), recall@1 0.742 -> 0.708 (**-0.033**)
- best fused config: **`hybrid_rrf60+rerank`** recall@5=0.975 mrr=0.908 (vs vector_only 0.983/0.853)
- does any fusion beat pure vector on this corpus? **NO**
- BM25 unique coverage (queries only the lexical channel finds): **0** / 60
- mechanism: with zero unique lexical coverage, RRF can only reorder the vector channel's own candidates using a second opinion that never adds a correct one. Hybrid losing to vector_only is then EXPECTED, not a bug - and the fix is a confidence gate or a cross-encoder, not a different RRF k.
- action: `hybrid_rrf60+rerank` is the candidate to promote; it must win on the per-case diff too (a mean can hide 8 wins / 8 losses), and it needs a unit test before it replaces the shipped default.
- scope warning: this is ONE corpus dominated by 351 homogeneous CSV rows. A conclusion of 'BM25 is useless' would be over-fitting; the defensible conclusion is about the FUSION RULE (rank-blind RRF has no confidence gate), which is corpus-independent.
